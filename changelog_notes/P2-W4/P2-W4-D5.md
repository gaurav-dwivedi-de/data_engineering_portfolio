#### 6. Perform Kubernetes rollback

The affected workload was the Dashboard Deployment.

The exact rollback command used was:

```bash
sudo k3s kubectl set image deployment/prediction-dashboard-deployment \
  prediction-dashboard=ghcr.io/gaurav-dwivedi-de/data_engineering_portfolio:46e6a9445960e822cb1f776d56357024e7e31a2e
```

Kubernetes returned:

```text
deployment.apps/prediction-dashboard-deployment image updated
```

The Dashboard rollout was then monitored with:

```bash
sudo k3s kubectl rollout status deployment/prediction-dashboard-deployment --timeout=180s
```

The rollout initially reported:

```text
Waiting for deployment "prediction-dashboard-deployment" rollout to finish: 1 old replicas are pending termination...
```

This message appeared twice.

The final result was:

```text
deployment "prediction-dashboard-deployment" successfully rolled out
```

This confirmed that Kubernetes created the replacement Dashboard pod using the previous image and terminated the old replica.

### Problems Faced During D5

#### 1. Rollback was performed on the affected Deployment

The rollback test was performed on:

```text
prediction-dashboard-deployment
```

It was not a rollback of the entire platform.

The following workloads were left running:

```text
PostgreSQL
MinIO
Airflow
FastAPI
```

Only the Dashboard Deployment image was changed back to the known-good SHA.

#### 2. Kubernetes terminated the old Dashboard replica during rollout

During the rollback, `kubectl rollout status` temporarily reported:

```text
1 old replicas are pending termination
```

The rollout then completed successfully.

This was normal Kubernetes rolling-update behaviour and did not result in a failed deployment.

#### 3. Persistent storage was intentionally preserved

The rollback command changed the Dashboard container image only.

No PostgreSQL or MinIO PVC deletion command was used during the rollback.

The post-rollback check confirmed:

```text
minio-data      Bound
postgres-data   Bound
```

and both StatefulSet pods remained running.

### Observations

The rollback used an immutable GHCR image SHA rather than a mutable tag such as `latest`.

The known-good image was:

```text
46e6a9445960e822cb1f776d56357024e7e31a2e
```

The newer D5 test release was:

```text
e0c3c955dd968de14dc9c6104a62a524228a2468
```

A later application release was:

```text
a560ef7e76d40457848c45f45b3bd3d353fadd8c
```

The Dashboard was then explicitly returned to:

```text
46e6a9445960e822cb1f776d56357024e7e31a2e
```

The rollback was therefore reproducible because the previous image remained available in GHCR.

The test demonstrated that Kubernetes can replace the Dashboard pod with a pod using a previously published immutable image without deleting the PostgreSQL or MinIO persistent volumes.
