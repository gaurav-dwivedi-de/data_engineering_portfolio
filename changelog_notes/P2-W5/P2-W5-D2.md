- P2-W5 D2: Configure Kubernetes Ingress with Traefik for unified Dashboard, FastAPI, and Airflow routing.
- Use the existing K3s Traefik ingress controller as the internal routing layer.
- Configure one Kubernetes Ingress resource to route requests to the Dashboard, FastAPI service, and Airflow API server.
- Verify each route through the Traefik address.
- Confirm that the Ingress has no configuration errors and that each backend is reachable through its configured path.

### Why this task was required

P2-W5 D1 established public access to the Weather Intelligence Platform through Cloudflare and the Cloudflare Quick Tunnel.

D2 establishes the Kubernetes routing layer behind that public entry point.

Instead of exposing each application directly to the public internet, Traefik provides a single Kubernetes ingress point and routes requests according to their URL path.

The routing architecture implemented was:

```text
Cloudflare / Quick Tunnel
        ↓
K3s Traefik
        ↓
weather-platform-ingress
        │
        ├── /          → prediction-dashboard-service:8051
        ├── /api       → fastapi-service:8000
        └── /airflow   → airflow-apiserver:8080
```

This gives the platform one ingress layer for the three application components while keeping FastAPI as an internal `ClusterIP` service and allowing the Dashboard and Airflow services to retain their existing NodePort configuration.

### Changelog

#### 1. Configure the Kubernetes Ingress resource

The existing Kubernetes Ingress was inspected with:

```bash
sudo k3s kubectl get ingress weather-platform-ingress -o yaml
```

The resulting configuration confirmed:

```yaml
spec:
  ingressClassName: traefik
  rules:
  - http:
      paths:
      - backend:
          service:
            name: prediction-dashboard-service
            port:
              number: 8051
        path: /
        pathType: Prefix
      - backend:
          service:
            name: fastapi-service
            port:
              number: 8000
        path: /api
        pathType: Prefix
      - backend:
          service:
            name: airflow-apiserver
            port:
              number: 8080
        path: /airflow
        pathType: Prefix
```

The Ingress also contained the Traefik entrypoint annotation:

```yaml
traefik.ingress.kubernetes.io/router.entrypoints: web
```

The Ingress status reported:

```text

  ingress:
  - ip: 10.0.0.245
```

This confirmed that the Ingress was associated with the Traefik load-balancer address.
