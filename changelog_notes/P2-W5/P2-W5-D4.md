### Why this task was required

D1 established the public Cloudflare hostname and HTTPS access.

D2 established the Traefik Kubernetes Ingress routes:

```text
/          → prediction-dashboard-service:8051
/api       → fastapi-service:8000
/airflow   → airflow-apiserver:8080
```

D3 verified the public HTTPS layer and Dashboard deployment.

D4 connects these pieces into one externally accessible application architecture.

The intended public integration is:

```text
https://ml.weather-intelligence.workers.dev/
        │
        ├── /          → Weather Prediction Dashboard
        ├── /api       → FastAPI
        └── /airflow   → Airflow
```

All three routes use the same public hostname and are then forwarded through the Cloudflare and Kubernetes routing layers.

Airflow also retains its existing NodePort:

```text
http://145.241.229.125:30080/
```

This provides a separate direct Kubernetes access path in addition to the unified public Ingress route.
