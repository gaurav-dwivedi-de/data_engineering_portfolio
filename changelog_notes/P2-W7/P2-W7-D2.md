### Why this task was required

P2-W7 introduces Spark MLlib alongside the existing scikit-learn workflow.
After D1 validated the current W7 feature-engineered dataset, D2 was required
to convert that data into a format that Spark MLlib can consume reliably.

The existing W7 Parquet dataset uses nanosecond timestamp precision. Spark
4.0.2 rejected that Parquet timestamp representation, so a separate
Spark-compatible dataset was required.

The MLlib preparation also needed to exclude the temporal boundary rows
identified during D1. The first three rows of each city do not contain valid
historical values for all required lag features, while the final row of each
city does not contain a valid next-hour target.

The canonical W7 feature-engineered Parquet file was kept unchanged. All
MLlib-specific datasets were created as separate outputs.

#### 4. Create a Spark-compatible MLlib input dataset

The canonical W7 Parquet file was read with PyArrow and only the `time`
column was converted from nanosecond precision to microsecond precision.

The command used was:

``` text
(.venv) gaurav@gauravs-Mac-mini data_engineering_portfolio % python -c 'import pyarrow.parquet as pq; import pyarrow as pa; src="./w7_feature_engineering/data/processed/w7_features_final.parquet"; dst="./w7_feature_engineering/data/processed/w7_mllib_input.parquet"; table=pq.read_table(src); idx=table.schema.get_field_index("time"); time_array=table["time"].cast(pa.timestamp("us")); table=table.set_column(idx,"time",time_array); pq.write_table(table,dst); print("Created:",dst)'
```

The output was:


#### 5. Create the clean MLlib dataset

The D1 validation established that 12 temporal boundary rows must be excluded:
four rows per city, consisting of the first three rows affected by lag-history
requirements and the final row without a valid next-hour target.

A Spark window ordered each city by `time`. Rows 1--3 and the final row were
excluded for each city.

The command used was:

``` text
(.venv) gaurav@gauravs-Mac-mini data_engineering_portfolio % python -c 'from pyspark.sql import SparkSession, Window; from pyspark.sql.functions import row_number, count, col; spark=SparkSession.builder.master("local[*]").appName("P2-W7-D2-Clean").getOrCreate(); src="./w7_feature_engineering/data/processed/w7_mllib_input.parquet"; dst="./w7_feature_engineering/data/processed/w7_mllib_clean.parquet"; df=spark.read.parquet(src); city=Window.partitionBy("city_London","city_Manchester").orderBy("time"); df=df.withColumn("_rn",row_number().over(city)).withColumn("_city_count",count("*").over(Window.partitionBy("city_London","city_Manchester"))); df=df.filter((col("_rn")>3)&(col("_rn")<=col("_city_count")-1)).drop("_rn","_city_count"); print("Clean MLlib rows:",df.count()); df.write.mode("overwrite").parquet(dst); print("Created:",dst); spark.stop()'
```

The output was:

``` text
Clean MLlib rows: 45852
Created: ./w7_feature_engineering/data/processed/w7_mllib_clean.parquet
```

The resulting dataset therefore contains the expected 45,852 clean MLlib
rows.

### Challenges and Resolutions

#### Challenge 1: Spark could not read the canonical W7 Parquet timestamp

The W7 feature-engineered Parquet file stored the `time` column using
nanosecond timestamp precision. Spark 4.0.2 rejected the Parquet schema.

**Resolution:** A separate `w7_mllib_input.parquet` dataset was created with
the `time` column converted to microsecond precision. The canonical W7
Parquet file was not modified.

#### Challenge 2: MLlib requires clean temporal boundaries

The first three rows of each city cannot provide valid historical lag
observations for the complete feature set, and the final row cannot provide
a valid next-hour target.

**Resolution:** A Spark window ordered each city by time and removed the
first three and final row from each city. This reduced 45,864 rows to
45,852 clean MLlib rows.

#### Challenge 3: Spark MLlib requires a vectorized feature representation

The W7 dataset contains individual engineered feature columns, whereas Spark
MLlib expects model inputs in a feature vector.

**Resolution:** Spark MLlib `VectorAssembler` combined the 27 selected
numeric feature columns into a single `features` vector.
