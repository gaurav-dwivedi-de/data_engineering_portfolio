### Challenges and Resolutions

#### Challenge 1: Terraform did not provide a safe direct update path for the existing boot volume

The existing OCI boot volume was already part of the VM infrastructure imported during D4. During D5, the objective was to validate an actual infrastructure change by increasing the boot volume from 47 GB to 200 GB.

The initial Terraform instance configuration did not produce the expected boot-volume resize operation.

**Resolution:** The OCI Terraform provider schema was investigated to determine how an existing boot volume could be represented independently. The investigation showed that the relevant boot-volume resource configuration did not provide a safe in-place update path for the existing volume.

#### Challenge 2: Experimental `oci_core_boot_volume` configuration proposed a replacement

An experimental `oci_core_boot_volume` configuration was tested against the existing boot volume. Terraform proposed a destroy-and-create replacement rather than an in-place resize.

**Resolution:** The replacement plan was not applied. The experimental boot-volume resource was removed from Terraform state and the temporary configuration file was deleted, avoiding a destructive replacement.

#### Challenge 3: Removing `source_details` caused provider validation failure

When the experimental boot-volume configuration was modified to remove `source_details`, the provider reported that the required `source_details` block was missing.

**Resolution:** The experimental resource approach was abandoned rather than forcing an invalid or destructive configuration. The existing OCI boot volume was resized directly through the OCI CLI.

#### Challenge 4: The OCI volume resize did not automatically expand the Linux filesystem

After the OCI boot volume reached 200 GB, Linux detected the larger disk, but the existing root partition and filesystem remained approximately 45.6 GB and 45 GB respectively.

**Resolution:** The disk was rescanned, `growpart` expanded `/dev/sda1`, and `resize2fs` expanded the ext4 filesystem online.

#### Challenge 5: Terraform initially detected the old 47 GB configuration

After the OCI volume was resized to 200 GB, Terraform initially identified that the configuration still represented the old 47 GB size.

**Resolution:** `instance.tf` was updated so that:

```hcl
boot_volume_size_in_gbs = 200
```

The final `terraform plan` then returned:

```text
No changes. Your infrastructure matches the configuration.
```
